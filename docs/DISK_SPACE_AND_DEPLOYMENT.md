# Disk space and deployment

Two things this file settles: what is safe to delete when the disk fills up,
and what may be uploaded to a production server.

Companions: [FLUTTER_PRODUCTION_DEPLOYMENT.md](FLUTTER_PRODUCTION_DEPLOYMENT.md)
(mobile build/release detail), [PRODUCTION_CHECKLIST.md](PRODUCTION_CHECKLIST.md)
(backend go-live).

## 1. Where the space actually goes

Measured 2026-09-09. **The important fact is which drive is under pressure.**

| Drive | Size | Free | Note |
|---|---|---|---|
| **D:** | 121 GB | **4 GB (97 % full)** | Holds `xampp/`, i.e. this project |
| C: | 304 GB | 89 GB | Holds every Flutter/Gradle/Android cache |

So the usual advice — "clear the Gradle and pub caches" — **does not help here**.
Those live on C:, which has 89 GB free. Deleting them costs hours of
re-download and frees nothing on the drive that is full.

What actually occupies D: (top level):

| Path | Size | Comment |
|---|---|---|
| `Sainiweb work` | 45 GB | Your work — untouched |
| `My DATA PERSONAL` | 29 GB | Personal — untouched |
| `All Software` | 27 GB | Installers — your call |
| `$RECYCLE.BIN` | **5.7 GB** | **Emptying the recycle bin is the single biggest safe win on D:** |
| `backup socityflow` | 5.6 GB | An old project backup — your call |
| `xampp` (whole) | 1.3 GB | Includes this project at 233 MB |

## 2. Project cleanup — what is safe

Everything below is generated, untracked by git, and regenerates on demand.
Verify with `git ls-files <path>` before deleting anything.

| Path | Typical size | Regenerated by |
|---|---|---|
| `societyflowmob/build/` | up to 1.2 GB | `flutter build …` |
| `societyflowmob/.dart_tool/` | ~98 MB | `flutter pub get` |
| `societyflowmob/android/.gradle/` | ~17 MB | next Gradle build (`flutter clean` does **not** remove it) |
| `societyflowmob/.kotlin/` | small | Gradle/Kotlin |
| `hs_err_pid*.log`, `replay_pid*.log` | up to 2.7 MB | JVM crash dumps — pure waste |
| `storage/logs/*.log` | 28 MB+ | truncate, don't delete the files |
| `storage/framework/{cache,views}/` | ~800 KB | `php artisan view:clear`, `cache:clear` |

```bash
# Flutter
cd societyflowmob
flutter clean && rm -rf android/.gradle
rm -f hs_err_pid*.log replay_pid*.log

# Laravel — truncate, so a running server keeps its file handle
: > storage/logs/laravel.log
php artisan view:clear && php artisan cache:clear
```

### Never delete

| Path | Why |
|---|---|
| `storage/app/public/` (77 MB) | **User uploads** — avatars, notice images, documents |
| `storage/backups/` | Pre-migration database backups |
| `storage/framework/sessions/` | Active logins; clearing signs everyone out |
| `vendor/` (91 MB) | Composer deps — app will not boot without it |
| `database/database.sqlite` | The development database |
| `societyflowmob/assets/**/placeholder.txt` | Load-bearing: `pubspec.yaml` declares those directories and Flutter fails the build if one is missing. Git does not track empty directories. |
| Anything `git ls-files` reports | Tracked source |

## 3. Global caches (all on C:)

Only worth touching if **C:** runs low. Categorised by cost.

**A — safe, pure waste**

| Path | Size |
|---|---|
| `~/.gradle/daemon/**/*.log` | ~61 MB — logs only; keep `registry.bin` and its `.lock` |
| `%TEMP%/flutter_tools.*` | ~98 MB |

**B — safe but re-downloaded (slow, needs network)**

| Path | Size | Cost of deleting |
|---|---|---|
| `~/.gradle/caches/8.14` + `modules-2` | 2.1 GB | Full dependency re-download on next build |
| `~/.gradle/caches/9.3.1`, `9.0.0` | 843 MB | Only if no other project uses Gradle 9.x |
| `~/.gradle/wrapper/dists/gradle-9.3.1-bin`, `-9.0.0-bin` | 290 MB | This project needs **8.14** only |
| Pub cache (`%LOCALAPPDATA%\Pub\Cache`) | 534 MB | `flutter pub cache clean`, then `pub get` per project |

**C — do NOT delete**

| Path | Size | Why |
|---|---|---|
| `~/.android/avd/` | **6.5 GB** | Emulator disk images — **user data**. Deleting destroys your Pixel_10_Pro virtual device and anything installed on it. Remove it through Device Manager if you genuinely don't want it. |
| SDK `system-images/` | 2.9 GB | Required by that emulator |
| SDK `ndk/` | 2.2 GB | `android/app/build.gradle.kts` declares `ndkVersion = flutter.ndkVersion` |
| SDK `platforms/`, `build-tools/`, `platform-tools/` | ~960 MB | Required to build |
| `%TEMP%` entries from other apps | 1 GB+ | Filmora, VS Code, etc. — not ours to delete |

## 4. Production upload rules

### Backend (Laravel)

Upload the application source, then build on the server.

**Never upload**

- `.env` — secrets. Create it on the server.
- `.git/` (39 MB)
- `vendor/` — run `composer install --no-dev --optimize-autoloader` on the server.
  Upload it only if the host has no Composer, and then it must be built with
  `--no-dev`.
- `node_modules/` — not applicable; this project has no `package.json`.
- `database/database.sqlite` — the dev database, contains **real resident PII**
- `storage/logs/*` — development logs
- `storage/backups/*` — database backups
- `tests/`, `phpunit.xml`, `.phpunit.result.cache`
- `.idea/`, `.vscode/`
- `composer.phar` (3.2 MB) — use the server's Composer

**Must exist on the server** (created there, not uploaded): `.env`,
`storage/` with its subdirectories writable, `bootstrap/cache/` writable,
`public/storage` symlink (`php artisan storage:link`).

### Mobile (Flutter)

**The Flutter project is never uploaded to the web server.** It compiles to
an installable artifact:

- **AAB** → Google Play Console (the required format)
- **APK** → only for direct/sideload distribution

If you self-host the APK for sideloading, the *only* mobile file in the
webroot is the `.apk` itself. Never `lib/`, `build/`, `.dart_tool/`,
`android/.gradle/`, `.idea/`, `local.properties`, or any `.jks`/`.keystore`.

## 5. Known toolchain problem (blocks Android builds)

As of 2026-09-09 the Android build fails immediately with:

```
ERROR: JAVA_HOME is not set and no 'java' command could be found in your PATH.
```

and, when pointed at Android Studio's bundled runtime:

```
Error: could not open `C:\Program Files\Android\Android Studio\jbr\lib\jvm.cfg'
```

**The JBR install is incomplete.** `jbr/lib/` contains only `modules` — a
working JBR has hundreds of files including `jvm.cfg` and `server/jvm.dll`.
It measures 64 MB against a normal ~300 MB. No other JDK is installed
(`Program Files\Java`, Eclipse Adoptium, `~/.gradle/jdks` are all absent).

This is an environment fault, not a source fault: the same source built an
APK (52.3 MB) and AAB (42.3 MB) earlier the same day.

**To repair — pick one:**

1. Android Studio → *Settings → Languages & Frameworks → Android SDK →
   SDK Tools*, or simply repair/reinstall Android Studio, then
   `flutter doctor -v` should report a JDK.
2. Install a standalone JDK 17 (Temurin), set `JAVA_HOME`, add
   `%JAVA_HOME%\bin` to `PATH`.
3. Point Flutter at a JDK explicitly:
   `flutter config --jdk-dir "<path-to-jdk>"`

Verify with `flutter doctor -v` before attempting a release build.
